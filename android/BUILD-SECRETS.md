# Android release signing secrets

Release builds need two secrets. They are **never** stored in git.

| Variable            | Used by                                              |
|---------------------|------------------------------------------------------|
| `KEYSTORE_PASSWORD` | `android/signed-release.sh`, `generate-signed-bundle.sh`, Gradle `release.properties` generation |
| `KEY_PASSWORD`      | Same as above (PKCS12 keystore: equals the store password) |

## Local builds

Export them in your shell (or a password-manager-backed env), then run the
scripts. Prefer env vars over positional args to keep secrets out of shell
history:

```bash
export KEYSTORE_PASSWORD='...' KEY_PASSWORD='...'
./android/signed-release.sh
# or: ./android/generate-signed-bundle.sh
```

`android/release.properties` (untracked, generated by the scripts) carries
these into Gradle. Never commit that file.

## CI

There is currently no release job in `.github/workflows` (only Go test
workflows exist). When one is added, it must define repository secrets
`KEYSTORE_PASSWORD` and `KEY_PASSWORD` and export them to the Gradle step,
e.g.:

```yaml
env:
  KEYSTORE_PASSWORD: ${{ secrets.KEYSTORE_PASSWORD }}
  KEY_PASSWORD: ${{ secrets.KEY_PASSWORD }}
```

Without them, `android/app/build.gradle` deliberately fails release tasks
instead of falling back to the debug keystore.

## Rules

1. `android/signed-release.sh` and `android/generate-signed-bundle.sh` are
   versioned via a `.gitignore` exception. They must never contain passwords.
2. `android/app/BoldBitcoinWallet.jks` and `android/release.properties`
   stay untracked, always.
3. If a secret is ever pasted into a tracked file, rotate it immediately:
   history does not forget.
